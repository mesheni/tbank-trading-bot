# Торговый бот T-Invest API: ML-прогноз + анализ новостной повестки

Учебно-исследовательский торговый робот для Т-Инвестиций:

* **данные** — официальный [T-Invest API](https://developer.tinkoff.ru/invest/intro/intro/) (REST-шлюз gRPC-контракта), история свечей и новости бесплатно;
* **прогноз** — бейзлайны (naive, MA, ARIMA, ETS) и градиентный бустинг LightGBM с walk-forward сравнением и выбором лучшей модели;
* **новости** — модель представлений (эмбеддинги e5, опционально) + тональность (ruBERT-трансформер или офлайн-лексикон) → агрегированный скор повестки;
* **торговля** — автоторговля в **sandbox** Т-Банка с риск-правилами (стоп-лосс, тейк-профит, лимит позиции), бэктест с комиссией и проскальзыванием.

> ⚠️ **Дисклеймер.** Проект образовательный. Никакая стратегия не гарантирует прибыль.
> Реальная торговля возможна только явной сменой `MODE=real` — делайте это осознанно и на свой риск.

## Быстрый старт

```bash
cd tbank-trading-bot
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt   # Windows
copy .env.example .env                          # и вписать токен
```

1. Получите токен: приложение **Т-Инвестиции** → профиль → «Настройки» → «Токен для T-Invest API»
   (или консоль на [developer.tbank.ru](https://developer.tbank.ru)). Для sandbox достаточно токена с правом «sandbox».
2. Впишите `T_INVEST_TOKEN` в `.env`.
3. Проверка связи: `.venv\Scripts\python cli.py smoke` — откроет sandbox-счёт, пополнит его на 1 млн руб.,
   скачает свечи и новости.

### Сертификат НУЦ Минцифры

При доступе к API из РФ цепочка TLS подписывается корнем НУЦ Минцифры, которого нет в
стандартном наборе certifi — без него `requests` падает с `SSL: CERTIFICATE_VERIFY_FAILED`.

Клиент решает это **автоматически**: положите файлы сертификатов (`Russian_Trusted_Root_CA.cer`,
`Russian_Trusted_Sub_CA.cer`, ...) в корень проекта или в папку `certs/` — при запуске они будут
найдены, объединены с certifi в общий бандл `data/ca_bundle.pem` и использованы для проверки.
Поддерживаются PEM и бинарный DER, в логе видно, какие файлы подхвачены.

Дополнительные опции (в `.env`):

```bash
# свой файл/папка с сертификатами вместо автопоиска
T_INVEST_CA_BUNDLE=C:\certs\russian_trusted_root_ca.pem

# крайний случай для диагностики: отключить проверку TLS вовсе (НЕБЕЗОПАСНО)
TLS_INSECURE=1
```

Сами файлы можно взять из [архива НУЦ Минцифры](https://gu-st.ru/content/lending/russian_trusted_root_ca.zip)
или установить в системное хранилище Windows двойным кликом (боту достаточно файлов в проекте).

## Команды

| Команда | Что делает | Нужен API |
|---|---|---|
| `cli.py smoke` | проверка токена, счёта, свечей, новостей | да |
| `cli.py download --days 720` | история свечей по всем тикерам → SQLite | да |
| `cli.py news` | свежие новости по инструментам → SQLite | да |
| `cli.py train` | walk-forward сравнение 6 моделей, сохранение лучшей | нет |
| `cli.py backtest` | бэктест стратегии с лучшей моделью, отчёты | нет |
| `cli.py run [--iterations N]` | торговый цикл бота в sandbox | да |
| `cli.py report` | позиции счёта и журнал сделок | да |

Типовой сценарий: `smoke` → `download --days 720` → `news` → `train` → `backtest` → `run`.

> Запуск на удалённом сервере 24/7 (Linux VPS, systemd, cron-переобучение, мониторинг) —
> пошаговая инструкция в [DEPLOY.md](DEPLOY.md).

## Консольный вывод

Вывод в терминал цветной: прибыль/позитив — зелёным, убыток/негатив — красным, решения бота
(BUY/SELL/HOLD) окрашены и выровнены, таблицы метрик и позиций — с выравниванием колонок и
выделением лучшей модели. Цвета работают через ANSI + VT-режим консоли Windows, без внешних
зависимостей, и **автоматически отключаются** при перенаправлении вывода в файл (`cli.py train > log.txt`
даёт чистый текстовый лог). Поведением можно управлять:

* `NO_COLOR=1` — принудительно выключить цвета;
* `FORCE_COLOR=1` — принудительно включить (например, для проверки).

Запись отчётов в файлы (`reports/*.csv|json|md`, журнал сделок, кривая капитала) сохраняется
независимо от раскраски консоли.

## Как смотреть результаты работы бота

* **`cli.py report`** — главный инструмент: капитал счёта и P&L к стартовому депозиту, открытые
  позиции с нереализованной прибылью, статистика журнала сделок, текущая кривая капитала.
* **`reports/equity_live.csv`** — кривая капитала живого прогона: бот пишет точку
  (время, капитал, свободные деньги, стоимость позиций) после каждой итерации. Можно открыть в
  Excel или построить график.
* **`reports/journal.csv`** — журнал сделок: время, тикер, действие, лоты, цена, причина решения
  («прогноз +0.012…», «стоп-лосс», «тейк-профит», «новостной фильтр» и т.д.).
* **Консоль `run`** — в лог каждой итерации печатается решение по каждому тикеру с обоснованием и
  итог капитала; то же самое пишется в лог при запуске с перенаправлением вывода.

Бэктестные результаты (до запуска бота) лежат там же: `reports/backtest_*.md`,
`equity_*.csv`, `trades_*.csv`, `metrics_*.json`, `train_summary.json`.

> Sandbox-счёт **не виден** в приложении Т-Инвестиций — он существует только через API,
> поэтому все результаты смотрятся командой `report` и файлами в `reports/`.

При первом запуске `run` бот сам пополняет счёт до `SANDBOX_INITIAL_RUB` (по умолчанию 1 млн),
относительно него считается P&L.

## Как это устроено

```
config.py               конфигурация (.env)
cli.py                  команды
bot.py                  главный цикл бота
features.py             признаки: доходности, лаги, RSI, MACD, ATR, Bollinger,
                        объёмы, календарь + новостные фичи; таргет = forward return
models/
  baseline.py           naive / persistence / MA / ARIMA / ETS
  boosting.py           LightGBM-регрессор доходности
  registry.py           walk-forward протокол, метрики (rmse, mae,
                        directional accuracy), выбор и сохранение лучшей
nlp/
  embedder.py           эмбеддинги новостей (multilingual-e5-small, опционально)
  sentiment.py          тональность: ruBERT-трансформер или лексикон (офлайн)
  agenda.py             повестка: взвешенный по свежести скор, импульс, темы
strategy.py             решение BUY/SELL/HOLD: сигнал + новостной фильтр + риск
backtest.py             walk-forward бэктест: комиссия, проскальзывание, SL/TP
tbank/
  rest.py               HTTP-транспорт: bearer-токен, троттлинг, ретраи на 429/5xx
  api.py                сервисы API: Users/Sandbox/Instruments/MarketData/
                        Orders/Operations + News
  market_data.py        чанковая выгрузка свечей, SQLite-хранилище
  trader.py             сделки sandbox и журнал сделок
```

### Инструменты

По умолчанию портфель — 16 ликвидных акций MOEX из разных секторов (`.env → TICKERS`):

| Сектор | Тикеры |
|---|---|
| Нефть и газ | GAZP, LKOH, ROSN, NVTK, TATN |
| Финансы | SBER, MOEX |
| Металлы и золото | GMKN, PLZL, CHMF, ALRS |
| Технологии / телеком / ретейл | YDEX, MTSS, MGNT, OZON |
| Транспорт | AFLT |

Список свободно меняется: укажите свои тикеры, затем `download` и `train`. Новые листинги с
короткой историей (< 500 свечей) автоматически пропускаются при обучении с предупреждением.

### Прогнозный контур

Скорость: блочные предсказания LightGBM и разреженное переобучение тяжёлых бейзлайнов (ARIMA/ETS —
раз в неделю торгового времени, их прогноз между фита́ми всё равно константный) позволяют обучать
весь портфель из 16 тикеров за ~15–25 минут; дешёвые бейзлайны (persistence, MA) честно
переобучаются на каждом баре.

1. Из свечей строится матрица признаков; таргет — доходность закрытия через `FORECAST_HORIZON` баров.
2. Все модели проходят одинаковый walk-forward протокол: обучаются только на прошлом,
   предсказывают на свежей четверти истории, переобучаются раз в 48 баров.
3. Ключевая метрика выбора — **strategy_sharpe**: годовой Sharpe стратегии «идём в сторону прогноза»
   на тестовом периоде. Выбор именно по экономической ценности, а не по RMSE: минимизировать RMSE
   на доходностях всегда выгодно модели «предсказывать ноль», которая не может торговать
   (она остаётся в таблице как эталон, но из выбора исключена).
4. Порог входа самокалибруется при обучении: `threshold = max(издержки за круг, 75-й процентиль
   |прогнозов| модели)`. В боте итоговый порог = `max(MIN_ABS_RETURN из .env, threshold из артефакта)`.
5. Если ни у одной модели strategy_sharpe не положителен, train пишет явное предупреждение:
   преимуществ нет, бот будет торговать редко или не торговать (защитное поведение).
6. Бэктест (`cli.py backtest`) считает предсказания walk-forward'ом — переобучаясь только на прошлом,
   как это будет делать бот. Финальная артефактная модель в бэктесте не используется: она обучена
   на всей истории, и оценка на её собственных данных дала бы фиктивно завышенный результат.
7. Лучшая модель сохраняется в `models_artifacts/`; бот на каждом цикле предсказывает доходность на горизонт.

### Новостной контур

1. `InstrumentsService/News` отдаёт общую ленту новостей Т-Банка (бесплатно, страницы по 1000 шт.).
   Серверная фильтрация по инструменту не поддерживается — привязка приходит внутри каждой новости
   (массив `instrumentId` с `instrumentUid`+`ticker`) и разрешается на нашей стороне.
2. Каждой новости проставляется тональность [-1, +1]: трансформер
   `Blanchefort/rubert-base-cased-sentiment` (если установлен `transformers`+`torch`) или офлайн-лексикон.
3. В SQLite новость хранится по связи «новость ↔ инструмент»; новость с несколькими тикерами даёт
   несколько строк, новости без привязки (макро) считаются общими для всех инструментов.
4. Повестка инструмента = экспоненциально взвешенный по свежести скор (полураспад 24ч) за окно 48ч,
   импульс (свежие против старых) и темы (кластеризация эмбеддингов, если установлен `sentence-transformers`).
5. Скор используется дважды: фильтр входа (не покупаем при `sentiment < NEWS_SENTIMENT_GATE`)
   и триггер выхода при резком ухудшении новостей.

### Стратегия и риск

* вход — прогноз выше `MIN_ABS_RETURN` **и** новостной фильтр пройден;
* размер позиции — `MAX_POSITION_PCT` от портфеля, кратно лоту, не больше свободных денег;
* выход — стоп-лосс `STOP_LOSS_PCT`, тейк-профит `TAKE_PROFIT_PCT`, разворот прогноза или негативные новости;
* в бэктесте стопы дополнительно проверяются по экстремумам бара (high/low).

### Замечание про SDK

Официальный gRPC SDK [`tinkoff-investments`](https://github.com/Tinkoff/invest-python) не публикует
колёса под Python 3.14, поэтому транспорт реализован поверх **официального REST-шлюза** того же API
(`/rest/<Service>/<Method>`, зеркален proto-контракту). Если хотите gRPC — создайте окружение на
Python ≤ 3.12 и `pip install tinkoff-investments`; остальной код от транспорта не зависит.

## Конфигурация (`.env`)

Все параметры описаны в [.env.example](.env.example): тикеры, таймфрейм, горизонт прогноза,
риск-параметры, комиссия/проскальзывание, интервал цикла, пути. По умолчанию SBER/GAZP/LKOH,
часовые свечи, горизонт 1 бар.

## Тесты

```bash
.venv\Scripts\python -m pytest tests/ -q
```

46 офлайн-тестов: признаки (корректность forward-таргета, отсутствие утечек), модели, стратегия
(все ветки решений), бэктест (инварианты капитала), NLP (лексикон, затухание, окна новостей),
SQLite-хранилище (upsert, фильтр некомплектных свечей, связи новостей), нормализация новостей,
сборка TLS-бандла.

## Ограничения и честные оговорки

* Лимиты API ~300 запросов/мин; клиент троттлит (0.25 c между запросами) и ретраит 429/5xx.
* История свечей ограничена глубиной на запрос (учтено чанкированием).
* Торговое расписание берётся из API (`TradingSchedules`), при недоступности — фиксированная сессия MOEX 09:50–18:50 МСК.
* В офлайн-бэктесте новостной фактор не моделируется (нет исторической ленты новостей по подписке) —
  он влияет только в живом цикле.
* Результаты на синтетике ничего не говорят о будущей доходности на реальном рынке.
